# OpenRobot CAN 프로토콜

[English](can_protocol.md) | 한국어

OpenRobot 모터 제어기의 classic CAN 명령 체계. 모든 값은 펌웨어 CAN 핸들러(`comm_can.c`,
`decode_msg_sid()`, 펌웨어 261119)에서 확인함.

현행 보드: SPN-MC V2 / V2R2, SPN-MC D14, SPN-MC D17_D20, VESCAT HIGH V2R2 / V2R3 / V2R4.
펌웨어 261119 이상에서 통신 끊김 감시(8절)와 새 위치 제어(0xA3, 0xA4)가 들어 있음.
다른 보드나 이전 펌웨어에서 동작이 다른 부분은 따로 표기함.

## 1. 버스

| 항목 | 값 |
|---|---|
| 프레임 | Classic CAN 2.0A, 표준 11비트 ID, DLC 8 |
| 비트레이트 | 공장 기본 1 Mbit/s (보드에서 변경 가능) |
| 요청 ID | `0x140 + motor_id` |
| 응답 ID | `0x140 + motor_id` (요청과 같은 ID) |
| 바이트 순서 | 리틀 엔디언. 비트 패킹된 MIT 프레임(0xC0)만 예외 |
| `data[0]` | 명령 코드. 응답에서 그대로 돌려줌 |

- 요청 하나에 응답 하나. 명령 처리 직후 응답함.
- 보드는 자기 `motor_id` 에만 응답함. 브로드캐스트 ID 없음.
- 요청과 응답이 같은 ID 를 씀. `data[0]` 으로 응답과 요청을 짝짓고, 어댑터가 송신 프레임을 되돌려 주는
  경우 자기 송신 프레임을 응답으로 착각하지 않도록 할 것.
- 쓰지 않는 응답 바이트는 0.
- 같은 모터에 다음 명령을 보내기 전에 응답(또는 타임아웃, 10 ms 면 충분)을 기다릴 것. 서로 다른 모터의
  명령은 섞어 보내도 됨.

### 모터 찾기

1~32(또는 사용 중인 범위)의 모든 ID 에 `0x92`(다회전 각도 읽기)를 보내고 응답을 모음. `0x92` 는 읽기만
하므로 안전함.

## 2. 단위와 공통 상태 응답

동작 명령(0x80, 0x81, 0x88, 0xA1~0xA6)과 `0x9C` 는 같은 형식의 상태로 응답함.

| 바이트 | 형식 | 의미 | 스케일 |
|---|---|---|---|
| 0 | u8 | 명령 코드 | |
| 1 | i8 | 모터 온도 | 1 °C |
| 2..3 | i16 | 모터 전류 (토크축, 부호 있음) | 33/2048 A (0.01611 A) |
| 4..5 | i16 | 모터축 속도 | 1 deg/s |
| 6..7 | u16 | 모터축 각도, 1회전 | 0..16383 = 0..360° |

모든 값은 **모터축 기준**(감속기 앞)이며, 보드에 설정된 사용자 방향을 따름. 0xC0 MIT 응답만 예외(6절).

모터 온도는 모터에 서미스터가 있을 때만 유효함.

## 4. 동작 명령

아래 명령은 모두 공통 상태(2절)로 응답함.

### 0x80 Motor off
`[0x80, 0, 0, 0, 0, 0, 0, 0]` → 모터 해제(토크 없음, 축 자유).

### 0x81 Motor stop
`[0x81, 0, ...]` → 0 deg/s 속도 제어. 모터가 현재 위치에 능동적으로 정지함.

### 0x88 Motor start
`[0x88, 0, ...]` → 듀티 0. 다른 제어 모드가 동작 중이면 먼저 해제함.

### 0xA1 전류(토크) 제어

| 바이트 | 형식 | 의미 |
|---|---|---|
| 4..5 | i16 | 전류 지령, LSB 당 33/2048 A |
| 6..7 | i16 | 댐핑, LSB 당 0.01, 0..100 으로 제한. 0 = 순수 전류 제어 |

토크 ≈ Kt × 전류. 부호는 사용자 방향을 따름.

### 0xA2 속도 제어 (DPS, eRPM)

| 바이트 | 형식 | 의미 |
|---|---|---|
| 1 | u8 | 0 = **DPS**, 1 = **eRPM** |
| 4..7 | i32 | DPS: 모터 속도, LSB 당 0.01 deg/s. eRPM: 전기 RPM, LSB 당 1 |

명령은 하나지만 제어기는 둘. 이 SDK 에서는 DPS, eRPM 으로 부름.

| | 속도 (DPS, 위치 추종) | 속도 (eRPM, VESC 속도 루프) |
|---|---|---|
| 방식 | 가속도 제한 프로파일이 목표 각도를 지령 속도로 진행시키고, 위치 루프가 그 각도를 따라감 | VESC 내장 속도 PID |
| 단위 | deg/s, 모터축 | 전기 RPM = 기계 RPM × 극쌍수 |
| 저속에서 부하가 걸릴 때 | 각도 오차가 누적되지 않음. 움직이는 목표 각도를 따라감 | 속도만 유지. 부하로 밀린 각도는 회복하지 않음 |
| 속도 0 | 현재 위치 유지 | 속도 0 유지, 위치는 유지 안 함 |
| 명령이 끊기면 | 계속 회전 (8절) | 마지막 명령 약 1 s 후 해제 |
| SDK | `speed_dps()` | `speed_erpm()` |

극쌍수는 이 프로토콜로 읽을 수 없음. eRPM 환산에는 모터 설정값을 사용.

**다른 동작 모드가 켜져 있으면 eRPM 은 무시됨.** DPS, 위치, MIT 등 OpenRobot 모드는 해제될 때까지 계속
동작하며, eRPM 명령으로는 끝나지 않음(측정: DPS 직후 eRPM 을 보내도 DPS 속도 유지). 먼저 0x80 을 보낼 것.
SDK 의 `speed_erpm()` 은 직전 동작 명령이 해제나 eRPM 이 아니면 0x80 을 먼저 보냄.

### 0xA3 위치 제어 (직접)

| 바이트 | 형식 | 의미 |
|---|---|---|
| 4..7 | i32 | 모터 다회전 각도 목표, LSB 당 0.01° |

목표가 속도 프로파일 없이 위치 루프로 바로 들어감. 큰 스텝은 제한됨.

- 60°(모터축)보다 큰 스텝은 10000 deg/s 속도 제한 이동으로 처리한 뒤 위치 루프로 넘김. 기준과 속도는 터미널
  명령 `or_limit` 으로 설정.
- 새 위치 제어(`or_ctl`)가 켜져 있으면, 위치 오차 전류가 약 3 A 가 되는 스텝이 더 작을 경우 그 값이 기준이
  되고, 이동은 0xA4 사다리꼴 궤적을 따름. 50 ms 미만 간격의 0xA3 은 연속 명령으로 처리함. 명령 주기를 측정해
  약 1.5 주기 지연으로 내부 시계에 맞춰 재생하므로 도착 시각의 지터가 모터에 전달되지 않음.

단발 점대점 이동에는 0xA4 를 쓸 것. 새 위치 제어 설명:
[관성 튜닝과 새 위치 제어](https://github.com/dongilc/openrobot-motor-tool/blob/master/docs/position_control_ko.md).

### 0xA4 속도 제한 위치 제어

| 바이트 | 형식 | 의미 |
|---|---|---|
| 2..3 | i16 | 속도 제한, LSB 당 1 deg/s, 유효 범위 1..25000 |
| 4..7 | i32 | 모터 다회전 각도 목표, LSB 당 0.01° |

속도 제한이 1..25000 을 벗어나면 별도 알림 없이 무시됨. 응답은 오지만 움직이지 않음.

새 위치 제어가 켜져 있으면 `or_ctl amax` 가속도(기본 25000 deg/s²)의 사다리꼴 궤적으로 이동함.

### 0xA5 듀티 제어

| 바이트 | 형식 | 의미 |
|---|---|---|
| 4..5 | i16 | 듀티, LSB 당 1/10000 (−10000..10000 = −100..100 %) |

### 0xA6 전류 브레이크

| 바이트 | 형식 | 의미 |
|---|---|---|
| 4..5 | i16 | 브레이크 전류, LSB 당 33/2048 A (크기만 사용) |

회전을 거스르는 방향으로 전류를 넣고, 축이 멈추면 놓음. 위치를 유지하지 않음.

## 5. 읽기와 설정 명령

### 0x9C 상태 읽기
요청 `[0x9C, 0...]`. 응답은 공통 상태(2절). 아무것도 바꾸지 않음.

### 0x9D 제어 모드, 상전류 읽기

| 바이트 | 형식 | 의미 |
|---|---|---|
| 1 | u8 | 제어 모드 (아래 표) |
| 2..3 | i16 | A상 전류, 1/64 A |
| 4..5 | i16 | B상 전류, 1/64 A |
| 6..7 | i16 | C상 전류, 1/64 A |

제어 모드: 0 없음, 1 해제, 2 전류 브레이크, 3 듀티, 4 전류, 5 댐핑 전류, 6 위치, 7 위치(다회전),
8 속도(타임아웃), 9 속도, 10 속도 제한 위치, 11 궤적, 12 MIT.

### 0x92 다회전 각도 읽기

| 바이트 | 형식 | 의미 |
|---|---|---|
| 1..7 | i56 | 모터 다회전 각도, LSB 당 0.01° (비트 55 부호 확장) |

### 0x93 출력 엔코더 읽기
출력축 엔코더가 있는 빌드만 응답함. 다른 빌드는 응답하지 않음.

| 바이트 | 형식 | 의미 |
|---|---|---|
| 1..2 | u16 | 출력 1회전 각도, LSB 당 360/65536° |
| 3..6 | i32 | 출력 다회전 각도, LSB 당 0.01° |
| 7 | u8 | 비트 0 엔코더 유효, 비트 1 보정표 로드됨, 비트 2 듀얼 보정표 로드됨 |

### 0x90 엔코더 읽기

| 바이트 | 형식 | 의미 |
|---|---|---|
| 1 | u8 | 엔코더 오류 비트 |
| 2..3 | u16 | 영점 보정 후 각도, 14비트 |
| 4..5 | u16 | 원시 각도, 14비트 |
| 6..7 | u16 | 영점 오프셋, 14비트 |

### 0x9E 엔코더 상태 읽기
진단 정보를 내는 엔코더용.

| 바이트 | 형식 | 의미 |
|---|---|---|
| 1..2 | u16 | 에어갭, µm |
| 3..4 | u16 | 신호 세기 |
| 5 | u8 | 읽기 오류율, LSB 당 0.5 % |
| 6 | u8 | CRC 상태 |
| 7 | u8 | 비트 0 오류, 비트 1 경고 |

### 0x9B fault 해제
응답 바이트 1 = 해제 후 fault 코드(해제되면 0). 통신 끊김 감시 작동 상태(8절)도 해제함. 이때 감시 동작(댐핑)은
다음 동작 명령까지 유지되므로 중력을 받는 관절이 떨어지지 않음.

### 0xB0 fault 이력 읽기
응답 바이트 1..7 = 최근 fault 코드 7개(7절).

### 0x30, 0x31, 0x32 위치 PID

| 바이트 | 형식 | 의미 |
|---|---|---|
| 2..3 | u16 | Kp × 1000 |
| 4..5 | u16 | Ki × 100000 |
| 6..7 | u16 | Kd × 100000 |

0x30 읽기, 0x31 RAM 쓰기(전원을 끄면 사라짐), 0x32 플래시 쓰기. 쓰기 명령은 값을 그대로 돌려줌.
새 위치 제어가 켜져 있으면 위치 루프 게인은 이 값 대신 측정한 관성으로 정해짐.

### 0xB1, 0xB2 전류 한계

| 바이트 | 형식 | 의미 |
|---|---|---|
| 1 | u8 | 게이트 드라이버 과전류 모드 |
| 2..3 | u16 | 모터 전류 한계, 0.01 A |
| 4..5 | u16 | 절대 전류 한계 (fault 발생), 0.01 A |
| 6..7 | u16 | 배터리 전류 한계, 0.01 A |

0xB1 읽기, 0xB2 플래시 쓰기. 음의 한계는 같은 값의 음수로 설정됨. 모터상 필요가 없으면 공장값을 유지할 것.

### 0x91 엔코더 영점 오프셋 쓰기
바이트 6..7 = 새 오프셋, 14비트. 플래시에 저장하고 다회전 각도를 초기화함. 응답 바이트 6..7 = 실제 저장된 오프셋.

### 0x19 현재 각도를 영점으로
현재 축 각도를 새 영점으로 잡아 플래시에 저장함. 다회전 각도를 초기화함. 응답 바이트 6..7 = 저장된 오프셋(14비트).

## 6. MIT 모드

**출력축 기준**(감속기 뒤) 임피던스 제어.

    torque = Kp × (p_des − p) + Kd × (v_des − v) + t_ff

순서: `0xC1` 진입 → `0xC0` 주기 전송 → `0xC2` 종료.

### 0xC0 MIT 제어 (비트 패킹, 빅 엔디언)

| 비트 | 필드 | 범위 | 폭 |
|---|---|---|---|
| data[1], data[2] | p_des | −12.56..12.56 rad | 16 |
| data[3], data[4] 상위 4비트 | v_des | −v_max..v_max rad/s | 12 |
| data[4] 하위 4비트, data[5] | Kp | 0..500 Nm/rad | 12 |
| data[6] | Kd | 0..5 Nm s/rad × Kd 배율 | 8 |
| data[7] | t_ff | −t_max..t_max Nm | 8 |

인코딩: `raw = round((x − min) / (max − min) × (2^bits − 1))`, 범위 밖은 잘라냄.
v_max, t_max 는 보드에 저장됨(0xC4). 공장값 45 rad/s, 33 Nm.

부호 있는 필드에서 0 은 정확히 표현되지 않음. 구간 폭이 짝수라 0 에 가장 가까운 코드가 반 스텝 어긋나 있고,
`x = 0` 은 가운데 코드 2^(bits−1)(p 32768, v 2048, t_ff 128)로 인코딩됨.

- SPN-MC V2 펌웨어 261109 이상은 가운데 코드를 정확히 0 으로 디코딩함. 다른 코드는 이전과 같으므로 호스트
  수정은 필요 없음.
- 이전 펌웨어(및 다른 보드)는 +max / (2^bits − 1) 로 디코딩함. t_ff 0 은 +t_max / 255(t_max 33 Nm 이면
  +0.13 Nm), v_des 0 은 +v_max / 4095. Kp = Kd = 0 이면 이 작은 토크로 자유 상태의 출력축이 천천히 돔.

응답:

| 바이트 | 형식 | 의미 |
|---|---|---|
| 1 | i8 | 모터 온도, °C |
| 2..3 | i16 | 모터 전류, 33/2048 A |
| 4..5 | i16 | **출력축** 속도, 1 deg/s |
| 6..7 | i16 | **출력축** 위치, LSB 당 12.56/32767 rad, MIT 영점 기준 |

### 0xC1 MIT 진입
구동을 켜고 위치 제어기로 **출력축을 현재 위치에 유지함**(이미 동작 중인 위치 명령이 있으면 그 목표 유지).
첫 `0xC0` 이 오면 즉시 MIT 제어로 바뀜. 원래 MIT(Mini Cheetah) 프로토콜은 진입 시 모든 값이 0 인 명령에서
시작해 관절이 힘을 잃지만, 여기서는 진입과 첫 명령 사이에 중력을 받는 관절이 처지지 않음.

응답 바이트 1 = 적용 중인 Kd 배율(0xC4 가 0 이 아닌 배율을 보고할 때만 신뢰. 이전 펌웨어는 값이 정해져 있지 않음).

### 0xC2 MIT 종료
모터를 해제함. 토크가 없어지고 출력축이 자유롭게 돎. 중력 부하가 걸린 관절은 떨어지므로, 먼저 정지시키거나
종료 대신 위치 명령으로 전환할 것.

### 0xC3 MIT 영점 설정
바이트 6..7 = i16 오프셋, 출력축 0.01°. 현재 위치가 이 값이 됨(0 = 현재 위치가 영점). 런타임 전용, 저장하지 않음.

### 0xC4 읽기 / 0xC5 쓰기 MIT 파라미터

| 바이트 | 형식 | 쓰기 (0xC5) | 읽기 응답 |
|---|---|---|---|
| 1 | u8 | v_max, rad/s | v_max |
| 2 | u8 | t_max, Nm | t_max |
| 3..4 | u16 | 모터축 Kt, 0.001 Nm/A (0 = 모터 설정값 사용) | **출력축** Kt = Kt × 감속비, 0.001 Nm/A |
| 5..6 | u16 | 감속비 × 100 | 감속비 × 100 |
| 7 | u8 | Kd 배율 1..8, 0 = 유지 | 적용 중인 Kd 배율 (0 = 배율 없는 펌웨어, 1 로 간주) |

둘 다 코드 0xC4 로 응답함. 모터가 도는 중의 쓰기는 거부되며, 이때 응답에는 이전 값이 실리므로 보낸 값과 비교할 것.

## 8. 안전

- **통신 끊김 (명령 감시).** 위치, 속도 명령은 한 번 보내고 유지하는 용도이므로 계속 실행됨. 전류, 브레이크,
  듀티, MIT 제어는 감시 대상이며, 100 ms 동안 동작 명령이 없으면 보드가 스스로 멈춤.

  | 마지막 명령 | 명령이 끊기면 |
  |---|---|
  | 0xA3, 0xA4 위치 | 목표 위치 유지 |
  | 0x81 정지 | 현재 위치 유지 (속도 0) |
  | 0xA2 속도 (DPS) | 그 속도로 **계속 회전** |
  | 0xA2 속도 (eRPM) | 마지막 명령 약 1 s 후 해제 |
  | 0xA1 전류, 0xA6 브레이크, 0xA5 듀티, 0x88 start | 감시 대상: 100 ms 후 댐핑 |
  | 0xC0 MIT | 감시 대상: 100 ms 후 댐핑 |
  | 0x80, 0xC2 | 해제 상태 유지 |

  - *댐핑*: 출력축 속도에만 반대하는 토크, `t = −kd × v`(기본 kd 2.0 Nm s/rad, 출력축). 움직이던 출력축은
    충격 없이 멈추고, 중력을 받는 관절은 떨어지지 않고 천천히 내려감. 정지 상태에서는 토크 0.
  - 감시가 작동하면 해제할 때까지 동작 명령을 무시함. 0x9B 는 다음 동작 명령까지 댐핑 유지, 0xC1 은 현재 위치
    유지(MIT 진입과 같음), 0x80 은 모터 해제. 상태 읽기(0x9C, 0x92 등)는 명령으로 치지 않으며 감시 시간을
    연장하지 않음.
  - 타임아웃(0 = 끔), 감시 대상 모드(위치, 속도 추가 가능), 동작(댐핑, 댐핑 후 정지하면 위치 유지, 해제)은
    터미널 명령 `or_wd` 로 설정하며 보드에 저장됨. EtherCAT 도 PDO 타임아웃 시 같은 동작을 함.
  - 감시가 없는 보드(문서 첫머리 참고)와 이전 펌웨어는 모든 모드에서 마지막 명령을 계속 실행함.

  호스트도 자체 루프를 감시하고 오류 시 0x80(또는 위치 유지)을 보내야 함. 이 저장소의 예제는 모두 그렇게 함.
  위치, 속도 제어 중 버스 자체가 끊기는 고장(커넥터, 케이블, 어댑터)은 감시로 잡히지 않으므로, 모터 전원을
  끊는 별도 수단(비상정지)을 둘 것.
- **전원.** 빠른 이동, 반전, 제동 시 전원에서 짧은 피크 전류를 끌어오고 에너지를 되돌려 보냄. 전류 제한이 있거나
  전류를 흡수하지 못하는 벤치 전원은 전압이 떨어지거나 올라 보드가 멈출 수 있음(저전압, 게이트 드라이버 fault).
  피크에 맞는 전원이나 배터리를 쓰고, 입력 전류 한계(모터 설정의 `l_in_current_max`, `l_in_current_min`)를
  전원이 공급, 흡수할 수 있는 값으로 설정할 것.
- 프로그램 종료 전 0x80 을 보낼 것. Ctrl+C 포함.
- 위치, 각도 값은 MIT 모드를 빼면 모터축 기준. 출력축 값은 감속비로 나눌 것.
